# 수집 PDF 분석: 상품별 구조화 데이터 추출

## 1. 가능 여부 요약

**가능합니다.**  
수집된 PDF(29CM 상품 상세 페이지 인쇄본)에서 **텍스트 추출**로 대부분 필드를 얻고,  
**룩북 무드·촬영장소·배경 톤**은 PDF 내 이미지를 추출해 **비전 모델**로 보완할 수 있습니다.

| 항목 | 추출 방식 | 난이도 | 비고 |
|------|-----------|--------|------|
| 상품명 | PDF 텍스트 | 쉬움 | 상단/제목 영역 |
| 브랜드명 | PDF 텍스트 | 쉬움 | 상품명 근처 또는 브랜드 영역 |
| 상세 카테고리명 | PDF 텍스트 | 쉬움 | 브레드크럼·태그 |
| 가격 | PDF 텍스트 | 쉬움 | 숫자+원 패턴 |
| 소재 | PDF 텍스트 | 쉬움 | 상세정보/테이블 |
| 케어방법 | PDF 텍스트 | 쉬움 | 상세정보/테이블 |
| 사이즈 | PDF 텍스트 | 쉬움 | 옵션/테이블 |
| 색상 | PDF 텍스트 | 쉬움 | 옵션/테이블 |
| 룩북 무드/톤 | 이미지 + 비전 모델 | 중간 | 텍스트에 없으면 이미지 분석 |
| 촬영장소 | 이미지 + 비전 모델 | 중간 | 실내/야외/스튜디오 등 |
| 배경색·톤 | 이미지 + 비전 모델 | 중간 | 색상·명도 추출 |

## 2. 기술적 접근

### 2.1 PDF 텍스트 추출

- **라이브러리**: `pdfplumber`(표·레이아웃 인식) 또는 `PyMuPDF`(fitz, 속도·이미지 추출 유리)
- **흐름**: PDF 파일 → 페이지별 텍스트/블록 추출 → 정규식 또는 LLM으로 필드 매핑
- **29CM PDF 특성**: A5 인쇄 웹페이지이므로 레이아웃이 일정하지 않을 수 있음.  
  → **LLM(프롬프트에 전체 텍스트 넣고 JSON 스키마 요청)** 사용 시 유지보수가 쉬움.

### 2.2 구조화 방식 (선택)

**A. 규칙 기반 (정규식·키워드)**  
- “소재”, “케이어”, “사이즈”, “색상” 등 라벨 뒤 문자열 추출  
- 빠르고 비용 없음. 레이아웃/표기 바뀌면 규칙 수정 필요.

**B. LLM 기반 (권장)**  
- 한 페이지 분량 텍스트를 LLM에 넣고,  
  “상품명, 브랜드명, 상세 카테고리, 가격, 소재, 케어방법, 사이즈, 사이즈_상세, 색상” 등을 JSON으로 추출하도록 지시  
- 레이아웃 변화에 강하고, 필드 추가·변경이 쉬움.  
- **구현**: `.env`에 `OPENAI_API_KEY` 설정 시 `scripts/analyze_pdfs.py` 및 웹 「PDF 분석 결과」에서 LLM 추출을 먼저 시도. 실패 시 규칙 기반 폴백. `--no-llm` 옵션으로 LLM 비활성화 가능.

### 2.3 룩북 무드·촬영장소·배경 톤

- **텍스트에 있을 때**: 위 텍스트 추출 단계에서 함께 추출.
- **텍스트에 없을 때**:
  1. PDF에서 **이미지 추출** (PyMuPDF 등)
  2. **비전 API**에 이미지 전달 → “무드, 톤, 촬영장소, 배경색·명도”를 짧은 문장/태그로 요청
  3. 결과를 동일한 상품 레코드에 필드로 저장

### 2.4 비전 API 제공처 (이미지 → 텍스트 설명)

| 제공처 | 제품/API | 비고 |
|--------|----------|------|
| **OpenAI** | GPT-4o, GPT-4 Turbo (vision) | [platform.openai.com](https://platform.openai.com) — API 키 발급 후 `openai` Python 패키지로 이미지 + 프롬프트 전달 |
| **Anthropic** | Claude 3 (Haiku/Sonnet/Opus) | [console.anthropic.com](https://console.anthropic.com) — 이미지 입력 지원, `anthropic` 패키지 |
| **Google** | Gemini 1.5 Pro/Flash (vision) | [aistudio.google.com](https://aistudio.google.com) 또는 Google Cloud — `google-generativeai` 패키지 |
| **Google Cloud** | Vision API | 이미지 라벨/텍스트 감지 등 전용 API (Cloud 콘솔에서 활성화) |
| **AWS** | Bedrock (Claude), Rekognition | AWS 콘솔 — Bedrock으로 Claude 비전 호출, Rekognition은 레이블/텍스트 전용 |
| **Azure** | Azure OpenAI (GPT-4V), Computer Vision | Azure 포털 — OpenAI 비전 또는 Computer Vision API |

- **공통**: 대부분 **API 키(또는 OAuth)** 발급 후 REST/공식 SDK로 이미지(base64 또는 URL) + 질문을 보내면 텍스트로 답변.
- **비용**: 호출당 과금(이미지 수·토큰 수 기준). 무료 티어가 있는 서비스(OpenAI·Anthropic·Google 등)는 가입 후 소량 무료 크레딧 제공.

## 3. 제안 파이프라인

```
[수집 PDF] → [PDF 텍스트 추출] → [LLM 구조화: 상품명·브랜드·가격·소재·케어·사이즈·색상 등]
                    ↓
              [PDF 이미지 추출] (선택)
                    ↓
              [비전 모델: 무드·촬영장소·배경 톤]
                    ↓
              [JSON/CSV 또는 DB 테이블로 저장]
```

```json

  "source_pdf": "여성_의류/01_12345.pdf",
  "상품명": "...",
  "브랜드명": "...",
  "상세_카테고리명": "...",
  "가격": 89000,
  "소재": "...",
  "케어방법": "...",
  "사이즈": ["S", "M", "L"],
  "색상": ["블랙", "화이트"],
  "룩북_무드_톤": "미니멀, 네츄럴",
  "촬영장소": "스튜디오",
  "배경색_톤": "화이트, 밝은 톤"
```

## 4. 구현 시 필요한 것

- **의존성**: `pdfplumber` 또는 `PyMuPDF`, (선택) OpenAI/Anthropic 등 비전 API 클라이언트
- **설정**: API 키(비전 사용 시), PDF 저장 경로(`pdfs/` 등)
- **모듈**:  
  - `pdfs/` 또는 지정 폴더 스캔  
  - PDF별 텍스트 추출 → LLM 호출 → JSON 저장  
  - (선택) PDF별 이미지 추출 → 비전 호출 → 필드 병합  
  - 결과를 CSV/JSON 파일 또는 Supabase 테이블에 저장

## 6. Gemini API 오류 대응

- **API 요청 이력이 없고 규칙 기반만 동작할 때**
  1. **.env 로드**: 앱이 `GEMINI_API_KEY`를 읽으려면 `.env`가 `os.environ`에 로드되어야 함. `web/app.py`에서 `load_dotenv()` 호출로 해결.
  2. **연결 테스트**: PDF 분석 페이지의 **Gemini API 연결 테스트** 버튼으로 1회 호출 후, 표시되는 에러 코드/메시지 확인.

- **HTTP 429 / ResourceExhausted / Quota exceeded**
  - 무료 한도(일일 요청 수·토큰) 초과이거나, 해당 모델이 무료 티어에서 제한될 수 있음.
  - **대응**: `.env`에 `GEMINI_MODEL=gemini-2.0-flash` 로 변경 후 재시도, 또는 다음 날 한도 리셋 후 재시도.
  - [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), [Usage](https://ai.dev/rate-limit) 참고.

- **에러 코드를 Gemini 지원에 문의할 때**
  - 연결 테스트 실패 시 화면에 나오는 **에러 코드/메시지 전체**를 복사해 전달하면 원인 파악에 도움이 됨.
