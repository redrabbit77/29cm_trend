# 프로젝트 원칙 (Constitution)

## 1. 코드 품질 원칙
- **명확성 우선**: 코드는 읽기 쉽고 이해하기 쉬워야 합니다.
- **모듈화**: 기능별로 명확하게 분리된 모듈 구조를 유지합니다.
- **에러 처리**: 모든 예외 상황에 대한 적절한 에러 처리를 구현합니다.
- **타입 힌팅**: Python 타입 힌팅을 적극 활용하여 코드의 가독성과 안정성을 높입니다.

## 2. 테스팅 표준
- **단위 테스트**: 핵심 비즈니스 로직에 대한 단위 테스트를 작성합니다.
- **통합 테스트**: 주요 워크플로우에 대한 통합 테스트를 구현합니다.
- **테스트 커버리지**: 최소 70% 이상의 테스트 커버리지를 목표로 합니다.

## 3. 사용자 경험 일관성
- **직관적인 UI**: Streamlit 기반 웹 인터페이스는 사용자가 쉽게 이해하고 사용할 수 있어야 합니다.
- **명확한 피드백**: 모든 사용자 액션에 대한 명확한 피드백을 제공합니다.
- **에러 메시지**: 사용자 친화적인 에러 메시지를 제공합니다.

## 4. 성능 요구사항
- **비동기 처리**: 데이터 수집 작업은 비동기로 처리하여 UI 블로킹을 방지합니다.
- **효율적인 데이터베이스 쿼리**: Supabase 쿼리는 최적화되어야 합니다.
- **리소스 관리**: 브라우저 자원과 메모리를 효율적으로 관리합니다.

## 5. 보안 및 프라이버시
- **API 키 보호**: 모든 API 키는 환경 변수로 관리하며 코드에 하드코딩하지 않습니다.
- **데이터 보안**: 수집된 데이터는 안전하게 저장되고 전송되어야 합니다.
- **봇 탐지 회피**: 인간 행동 모사를 통해 봇 탐지를 우회합니다.

## 6. 비용 최적화
- **무료 티어 활용**: Supabase Free Tier와 Streamlit Community Cloud를 최대한 활용합니다.
- **로컬 자원 활용**: 데이터 수집은 로컬 PC 자원을 활용합니다.
- **불필요한 리소스 방지**: 사용하지 않는 서비스나 리소스를 생성하지 않습니다.

## 7. 기술 결정 가이드라인
- **기술 스택 준수**: PRD와 TRD에 명시된 기술 스택을 엄격히 따릅니다.
  - Python 3.10+
  - Streamlit (웹 UI)
  - Supabase (데이터베이스)
  - Playwright (브라우저 자동화)
  - PyAutoGUI, pyperclip (인간 행동 모사)
- **의존성 최소화**: 필요한 라이브러리만 사용하고 불필요한 의존성을 추가하지 않습니다.
- **버전 관리**: 모든 의존성의 버전을 명시적으로 관리합니다.

## 8. 개발 프로세스
- **점진적 개발**: 작은 단위로 기능을 구현하고 테스트합니다.
- **문서화**: 주요 기능과 API는 명확하게 문서화합니다.
- **코드 리뷰**: 모든 변경사항은 검토 후 병합합니다.
