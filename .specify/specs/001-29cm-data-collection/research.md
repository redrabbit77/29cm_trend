# 기술 리서치 문서

## 1. Playwright 스크래핑 전략

### 1.1 29CM 웹사이트 구조 분석 필요사항
- [ ] BEST 상품 목록 페이지 URL 패턴 분석
- [ ] 상품 상세 페이지 URL 패턴 분석
- [ ] 페이지 로딩 방식 (SPA vs SSR)
- [ ] 동적 콘텐츠 로딩 방식 (무한 스크롤, 페이지네이션 등)
- [ ] 이미지 로딩 방식 (lazy loading 등)

### 1.2 봇 탐지 우회 전략
- **User-Agent 로테이션**: 다양한 브라우저 User-Agent 사용
- **브라우저 핑거프린팅**: 실제 브라우저 환경 시뮬레이션
- **행동 패턴**: 인간의 불규칙한 행동 패턴 모사
- **요청 간격**: 랜덤 딜레이 적용

### 1.3 Playwright 최적 설정
```python
# 브라우저 컨텍스트 설정 예시
context = await browser.new_context(
    viewport={'width': 1920, 'height': 1080},
    user_agent='Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
    locale='ko-KR',
    timezone_id='Asia/Seoul',
    permissions=['geolocation'],
    geolocation={'latitude': 37.5665, 'longitude': 126.9780},  # 서울
    color_scheme='light',
    extra_http_headers={
        'Accept-Language': 'ko-KR,ko;q=0.9,en-US;q=0.8,en;q=0.7'
    }
)
```

## 2. Supabase 사용 전략

### 2.1 Free Tier 제한사항
- **데이터베이스**: 500MB 저장 공간
- **Storage**: 1GB 저장 공간
- **API 요청**: 월 50,000 요청
- **Realtime 연결**: 동시 200 연결

### 2.2 최적화 전략
- **이미지 압축**: 업로드 전 이미지 압축
- **배치 처리**: 여러 요청을 배치로 처리
- **인덱스 최적화**: 자주 조회되는 컬럼에 인덱스 생성
- **데이터 정리**: 오래된 데이터 주기적 정리

### 2.3 Realtime 구독 최적화
- 필요한 테이블만 구독
- 구독 해제 시점 관리
- 연결 재시도 로직 구현

## 3. 인간 행동 모사 알고리즘

### 3.1 베지어 곡선 알고리즘
- **3차 베지어 곡선**: 시작점, 끝점, 2개의 제어점
- **제어점 생성**: 랜덤하게 생성하여 자연스러운 경로
- **포인트 간격**: 일정하지 않은 간격으로 포인트 생성

### 3.2 마우스 이동 시뮬레이션
- **속도 변화**: 가속/감속 패턴 적용
- **미세한 움직임**: 목표 지점 주변에서 미세한 움직임
- **대기 시간**: 클릭 전 짧은 대기 시간

### 3.3 키보드 입력 시뮬레이션
- **타이핑 속도**: 인간의 타이핑 속도 시뮬레이션 (랜덤 딜레이)
- **오타 및 수정**: 가끔씩 오타 후 백스페이스로 수정 (선택사항)

## 4. 이미지 처리 전략

### 4.1 이미지 다운로드
- **비동기 다운로드**: 여러 이미지를 병렬로 다운로드
- **재시도 로직**: 실패 시 재시도
- **크기 제한**: 너무 큰 이미지는 리사이즈

### 4.2 이미지 압축
- **JPEG 품질**: 85% 품질로 압축
- **최대 크기**: 1920x1920 픽셀 제한
- **라이브러리**: Pillow 사용

### 4.3 Supabase Storage 업로드
- **배치 업로드**: 여러 이미지를 한 번에 업로드
- **업로드 실패 처리**: 실패한 이미지 재시도 큐에 추가
- **진행률 추적**: 업로드 진행률 표시

## 5. 에러 처리 및 복구 전략

### 5.1 네트워크 에러
- **재시도**: 지수 백오프(exponential backoff) 전략
- **최대 재시도**: 3회
- **타임아웃**: 30초

### 5.2 파싱 에러
- **유연한 셀렉터**: 여러 셀렉터 시도
- **부분 데이터 저장**: 일부 데이터라도 수집 가능하면 저장
- **에러 로깅**: 상세한 에러 정보 로깅

### 5.3 작업 실패 복구
- **체크포인트**: 작업 진행 상황 저장
- **재시작**: 실패한 작업부터 재시작
- **부분 완료**: 일부 완료된 작업은 유지

## 6. 성능 최적화

### 6.1 데이터베이스 쿼리 최적화
- **인덱스 활용**: WHERE 절에 사용되는 컬럼에 인덱스
- **JOIN 최적화**: 필요한 컬럼만 SELECT
- **페이지네이션**: LIMIT/OFFSET 사용

### 6.2 메모리 관리
- **브라우저 인스턴스**: 하나의 인스턴스 재사용
- **이미지 버퍼**: 다운로드 후 즉시 업로드하여 메모리 해제
- **가비지 컬렉션**: 주기적인 메모리 정리

### 6.3 비동기 처리
- **asyncio 활용**: 비동기 I/O 작업
- **병렬 처리**: 여러 상품 페이지 동시 처리 (제한적)
- **큐 관리**: 작업 큐를 통한 순차 처리

## 7. 테스팅 전략

### 7.1 단위 테스트
- **인간 행동 모사 모듈**: 베지어 곡선, 딜레이 등
- **데이터 파싱 로직**: HTML 파싱 및 데이터 추출
- **Supabase 클라이언트**: CRUD 작업

### 7.2 통합 테스트
- **전체 워크플로우**: 작업 생성부터 완료까지
- **Realtime 동기화**: 상태 업데이트 동기화
- **에러 복구**: 네트워크 에러 시나리오

### 7.3 E2E 테스트
- **실제 웹사이트**: 29CM 웹사이트에서 실제 테스트 (제한적)
- **모의 웹사이트**: 로컬에서 모의 웹사이트 구축하여 테스트

## 8. 보안 고려사항

### 8.1 API 키 보안
- **환경 변수**: 모든 키는 환경 변수로 관리
- **키 로테이션**: 주기적인 키 변경
- **접근 제한**: IP 화이트리스트 (가능한 경우)

## 9. 모니터링 및 알림

### 9.1 로그 수집

- **데이터 수집량**: 일일 수집 데이터량

### 9.3 알림 (향후 구현)
- **작업 완료 알림**: 작업 완료 시 알림
- **에러 알림**: 심각한 에러 발생 시 알림
- **용량 경고**: 저장 공간 부족 시 경고

- **에이전트 다중화**: 여러 에이전트 동시 실행
