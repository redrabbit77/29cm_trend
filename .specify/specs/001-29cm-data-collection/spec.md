# 스펙: 29CM 브랜드 포지셔닝 맵 구축을 위한 데이터 수집 엔진

## 1. 프로젝트 개요

### 1.1 배경
29CM의 감도 높은 큐레이션 데이터를 바탕으로 시장 내 브랜드들의 포지션을 분석하고자 합니다.

### 1.2 목적
베스트 상품의 정량/정성 데이터를 수집하여 브랜드 간의 상대적 위치(컨셉, 가격, 무드 등)를 시각화하는 브랜드 맵(Brand Map) DB를 구축합니다.

### 1.3 타겟 유저
- 브랜드 마케터 및 시장 분석가
- 29CM 입점 및 신규 브랜드 런칭 준비자

## 2. 사용자 시나리오

### 시나리오 1: 데이터 수집 시작
1. 사용자는 웹 대시보드(Streamlit)에서 수집하고자 하는 카테고리를 선택합니다.
2. '수집 시작' 버튼을 클릭합니다.
3. 시스템이 로컬 에이전트를 통해 29CM 홈페이지를 사람처럼 서핑하며 데이터를 수집합니다.
4. 수집 진행 상황이 실시간으로 대시보드에 표시됩니다.

### 시나리오 2: 브랜드 맵 시각화
1. 수집 완료 후, 사용자는 브랜드 맵 시각화 도구에 접근합니다.
2. X축과 Y축을 설정합니다 (예: 가격 vs 컨셉, 무드 vs 가격 등).
3. 브랜드 위치가 실시간으로 그래프에 표시됩니다.
4. 사용자는 필터링 및 정렬 기능을 사용하여 데이터를 탐색합니다.

## 3. 기능 요구사항

### 3.1 데이터 수집 (Human-like Scraping)

#### 3.1.1 수집 대상
- **카테고리**: 여성/남성 카테고리별
  - 의류
  - 가방
  - 슈즈
  - 액세서리
  - 주얼리
- **상품**: BEST 1~10위 상세페이지

#### 3.1.2 수집 항목
각 상품 페이지에서 다음 정보를 수집합니다:
- 브랜드명
- 상품명
- 가격
- 사이즈
- 색상
- 룩북 이미지 (여러 장)
- 상세 설명 텍스트

#### 3.1.3 인간 행동 모사 방식
- **마우스 이동**: 베지어 곡선(Bezier Curve) 알고리즘을 사용하여 자연스러운 마우스 경로 생성
- **텍스트 수집**: 마우스 드래그 → `Ctrl+C` → `pyperclip.paste()`로 텍스트 수집
- **이미지 저장**: 우클릭 → 단축키 'V'(이미지 저장) → 파일명 자동 입력 흐름 모사
- **불규칙한 행동 패턴**: 봇 탐지 시스템 우회를 위해 고정된 패턴이 아닌 불규칙한 행동 패턴 적용

### 3.2 데이터 관리 및 분석

#### 3.2.1 데이터베이스화
- 수집된 데이터를 브랜드/카테고리별로 정규화하여 Supabase에 저장
- 데이터 스키마:
  - `brands` 테이블: 브랜드 정보
  - `products` 테이블: 상품 정보
  - `product_images` 테이블: 상품 이미지 정보
  - `categories` 테이블: 카테고리 정보
  - `collection_tasks` 테이블: 수집 작업 상태 관리

#### 3.2.2 이미지 분석 (향후 기능)
- 룩북의 배경색 분석
- 촬영 장소 태깅
- 모델 분위기 태깅

### 3.3 시각화 대시보드

#### 3.3.1 테이블 뷰
- 수집된 RAW 데이터를 엑셀 형태로 조회
- 필터링 기능:
  - 브랜드별
  - 카테고리별
  - 가격 범위별
  - 수집 날짜별
- 정렬 기능: 모든 컬럼에 대해 오름차순/내림차순 정렬
- 데이터 내보내기: CSV, Excel 형식으로 내보내기

#### 3.3.2 브랜드 맵
- 사용자 설정 축(Axis)에 따른 실시간 포지셔닝 그래프 생성
- 축 설정 옵션:
  - 가격
  - 컨셉 (텍스트 분석 기반)
  - 무드 (이미지 분석 기반)
  - 브랜드 인기도
- 인터랙티브 차트: 브랜드 클릭 시 상세 정보 표시
- 줌 및 팬 기능

## 4. 비기능 요구사항

### 4.1 보안 회피
- 봇 탐지 시스템 우회를 위해 고정된 패턴이 아닌 불규칙한 행동 패턴 적용
- 요청 간 랜덤 딜레이
- User-Agent 로테이션
- 쿠키 및 세션 관리

### 4.2 비용 최적화
- 서버 운영비 0원을 목표로 무료 클라우드 티어 및 로컬 자원 활용
- Streamlit Community Cloud (무료)
- Supabase Free Tier (무료)
- 로컬 PC 자원을 활용한 데이터 수집

### 4.3 성능
- 데이터 수집 작업은 백그라운드에서 비동기로 실행
- UI는 수집 작업 중에도 반응형으로 유지
- 대량 데이터 처리 시 배치 처리

### 4.4 확장성
- 새로운 카테고리 추가 용이
- 새로운 수집 항목 추가 용이
- 향후 이미지 분석 기능 추가 용이

## 5. 시스템 아키텍처

### 5.1 하이브리드 구조
- **Web Control Plane**: Streamlit 기반 웹 UI
- **Local Execution Plane**: 로컬 PC에서 실행되는 데이터 수집 에이전트
- **Central DB**: Supabase 기반 중앙 데이터베이스

### 5.2 데이터 동기화 프로세스
1. **Web (Streamlit)**: 사용자가 수집 요청을 Supabase `tasks` 테이블에 저장
2. **Local Agent**: `tasks` 테이블을 실시간 감지 후 수집 루틴 실행
3. **Storage**: 수집된 이미지는 로컬 저장 후 Supabase Storage로 업로드
4. **상태 업데이트**: 수집 진행 상황을 `tasks` 테이블에 실시간 업데이트
